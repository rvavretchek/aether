## Deferred from: code review of 1-1-aether-admin-new-scaffolding (2026-08-31)

- **TOCTOU + symlink na criação/rollback do diretório alvo** — `isEmptyOrMissing` e `mkdir` são checados separadamente (sem lock), e o `rm` de rollback não confere se `targetDir` é um symlink antes de apagar recursivamente. Baixa probabilidade no uso real (dev único, local, sem invocação concorrente esperada); custo de blindagem completa não compensa agora. [src/cli/commands/new.ts]
- **Versões de dependência congeladas sem mecanismo de atualização** — todo projeto gerado por `aether-admin new` fica preso às versões literais escritas no código do gerador no momento em que foram escritas. Inerente a qualquer scaffolding baseado em template; já verificado que a combinação atual instala e funciona de verdade. Revisitar quando `aether-admin` precisar de um processo de release formal.
- **Nenhum `LICENSE` gerado no projeto scaffolded** — apesar do próprio `aether-admin` se declarar MIT em seu `package.json`, o projeto que ele gera não recebe um arquivo de licença. Melhoria de qualidade de vida, não exigida por nenhuma AC da Story 1.1.
- **`API_PORT`/`WEB_PORT` não-numéricos no ambiente viram `NaN` sem fallback** — `Number(process.env.API_PORT ?? 3001)` não valida o resultado. Ferramenta de dev local, risco real baixo. [src/scaffolding/templates/api.ts, src/scaffolding/templates/web.ts]

## Deferred from: code review of 2-1-login-jwt-refresh (2026-09-02)

- **`aether-admin new` nunca aplica as migrations do Prisma (reclassificado de Patch pra Defer durante a aplicação)** — o pipeline roda `generatePrismaClient` (só codegen) mas nunca `prisma migrate deploy`. Um projeto recém-scaffolded não tem tabelas; o primeiro `login` falha com "relation users does not exist". **Não corrigido agora porque o fix óbvio (chamar migrate dentro de `runNew`) quebraria o comando de verdade** — nada nele sobe o Postgres primeiro, e `aether-admin dev` (FR-4, quem orquestraria Docker Compose + migrate + servidores) ainda é só um placeholder. Aplicar migrations é responsabilidade de `aether-admin dev`, não de `new` — bloqueado até a story de Epic 1 que implementa FR-4. [src/cli/commands/new.ts]
- **Negação de build script do pnpm (`prisma:false`) generalizada sem validação cross-platform** — `pnpm-workspace.yaml` desabilita o script de preinstall do `prisma` pra todo projeto gerado, a partir de um bug reproduzido isolado só numa máquina Windows/Git Bash/pnpm 11.24. Nunca testado em Linux/macOS ou outras versões do pnpm — se a suposição "é só telemetria não-essencial" estiver errada em algum desses ambientes, todo consumidor herda silenciosamente um lifecycle script desabilitado por um bug de outra pessoa. [src/scaffolding/templates/root.ts]
- **Teste de rollback de `generatePrismaClient` não verifica ordem real de execução** — o novo teste em `new.test.ts` confirma que os mocks foram conectados na ordem esperada, não que a implementação de fato exige que `installDependencies` complete antes de `generatePrismaClient` rodar. [src/cli/commands/new.test.ts]
- **`AuthProvider.verifyToken` (AC #10, Zero Trust) adiado formalmente pra Epic 3** — decisão do Boss no code review desta story: a Story 2.1 entrega só a *emissão* do JWT (`SignJWT`/HS256), nunca a verificação (`jwtVerify` com `algorithms` explicitamente fixado). Não implementado agora porque não há nenhum consumidor real do access token ainda (nenhuma rota protegida existe até a Epic 3 construir o middleware de enforcement). **Ao criar a primeira story da Epic 3 que exige `ctx.user` autenticado, garantir que `AuthProvider.verifyToken` seja implementado e adicionado à interface antes/junto do middleware — não deixar a AC #10 original desta story cair no esquecimento.** [src/scaffolding/templates/auth.ts, interface `AuthProvider`]
