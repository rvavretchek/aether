## Deferred from: retrospectiva do Épico 3 (2026-10-01)

- **`prettier --write .` roda no repositório inteiro antes do ponto-de-não-retorno de `generate module`; rollback não desfaz reformatação colateral de arquivos pré-existentes não relacionados caso a migration falhe depois** — puramente cosmético (conteúdo semântico idêntico), mas quebra a garantia implícita de "rollback restaura o estado original". [src/cli/commands/generate-module.ts]
- **`rollback()` de `generate module` engole os próprios erros silenciosamente** (`.catch(() => undefined)` em cada etapa) — se a própria reversão falhar parcialmente, o chamador só vê o erro original, sem saber que o projeto pode ter ficado num estado parcialmente revertido. - **Janela de mensagem enganosa no retry após sucesso parcial**: se o processo morrer entre `runMigrate` ter sucesso e `generatePrismaClient` completar, um retry do mesmo nome bate na checagem de colisão genérica ("já foi gerado antes?") em vez da mensagem específica que já existe pro caso síncrono ("rode `pnpm --filter db run generate` manualmente"). Janela rara (precisa de crash no meio exato), recuperação manual ainda é possível. [src/cli/commands/generate-module.ts]
- **`buildModuleMigrationSql` não tem blindagem própria contra SQL injection** — função pura, interpola `slug` direto em literais SQL sem escaping próprio; segurança de hoje vem 100% do regex de `validateModuleName` (em outro módulo). Relevante quando `--from <arquivo>` (extensão futura já documentada) for desenhado, por ler slugs de fonte menos confiável. [src/codegen/module-migration.ts]
- **(Reconfirmado por 2 lentes independentes do retro, sem informação nova)** `RESERVED_MODULE_NAMES` só bloqueia formas singulares, não os nomes de tabela reais (plural/snake_case: `modules`, `resources`, `role_assignments`, etc.) — mesmo item já aceito no review da Story 3.3, nenhuma ação nova.
- **(Reconfirmado, sem informação nova)** `mountRouterInRootRouter` — ambiguidade entre colisão real e âncora não encontrada, sem teste com `root-router.ts` editado à mão. Sugestão concreta pra quando o arquivo for tocado de novo: adicionar esse teste.
- **(Refinado)** Duas chamadas `generate module` concorrentes pro mesmo slug — mecanismo exato é leitura única de `schema.prisma`/`root-router.ts` reaproveitada tanto pro merge quanto pro rollback (last-write-wins), não só "falta de lock" genérico.
- **(Reconfirmado, estendido)** Sem validação de argumentos posicionais extras/flag-like — já deferido desde a Story 3.2 pra `migrate`; agora também relevante pra `generate module` (N nomes numa chamada tornam um flag typo plausível, ex.: `generate module pedidos --dry-run` tentaria gerar um módulo chamado `--dry-run`).
- **Ação proposta, não aplicada**: construir um harness reutilizável de validação pós-geração (`aether-admin new` → install → `prisma generate` → typecheck → lint → format:check → test) — a epic redescobriu 3 vezes (Stories 3.1, 3.3 duas vezes) que bugs reais só aparecem rodando de verdade contra Postgres, sempre reinventando manualmente os mesmos ~5 comandos. Ver `epic-3-retro-2026-10-01.md`.
